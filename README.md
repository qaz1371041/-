# 📺 IPTV 直播源全自动流水线系统

## 📖 一、 项目简介
本项目是一个基于 **GitHub Actions** 的 IPTV 直播源“无人值守”自动化维护系统。
彻底告别手动找源、手动测速的痛苦，实现了一套完整的**工业级流水线**：
`自动抓取第三方源` ➡️ `智能别名匹配` ➡️ `ffprobe 真实播放测速` ➡️ `秋后算账(劣质源拉黑)` ➡️ `按模板生成高清播放列表`。

│
├── output/                        # 📦 产出目录：生成的最终播放列表 (由 Actions 自动提交)
│   ├── result.txt                 #    - txt 格式播放列表
│   └── result.m3u                 #    - m3u 格式播放列表
│
├── main.py                        # 🧠 大脑：系统主入口，编排 抓取->测速->算账->生成 流程
├── scraper.py                     # 🕷️ 触角：负责下载第三方源、读取黑名单、进行别名匹配
├── speed_test.py                  # ⚡ 引擎：调用 ffprobe 进行高并发真实播放测速与记账
├── judge.py                       # ⚖️ 法官：秋后算账，根据测速成绩单自动生成黑名单
├── generator.py                   # 🖨️ 打印机：严格按照 demo.txt 的顺序和分类输出最终文件
│
├── demo.txt                       # 📋 模板：定义最终需要的频道列表、顺序及分类
├── alias.txt                      # 📖 字典：全网最全的频道别名映射表 (支持正则)
├── .gitignore                     # 🛡️ 护盾：防止 __pycache__ 等本地缓存文件污染仓库
└── README.md                      # 📖 说明：您正在阅读的项目文档

🔧 四、 Fork 了仓库怎么改？（修改指南）
如果您 Fork 了本项目，想要打造属于自己的 IPTV 列表，请按照以下 4 步进行：
1. 换源：修改抓取目标
改订阅源：打开 config/config.ini，在 [scraper] 下的 sources 列表中，替换或添加您自己收集的 IPTV 源地址。
改输出模板：打开 demo.txt，按照您想要的频道顺序和分类，写下您需要的频道名称（例如：CCTV-1, 央视）。
2. 改规则：调整别名与测速
改别名匹配：打开 alias.txt，如果您发现某个频道抓不到，可以在对应的主名后面，用逗号 , 追加它在第三方源里可能出现的别名或正则表达式。
改测速严格度：打开 speed_test.py，搜索 TIMEOUT 调整超时时间，或搜索 CONCURRENCY 调整并发测速的线程数。
3. 改频率：调整自动运行时间
打开 .github/workflows/build-and-update.yml 文件。
找到 cron: '0 22 * * *'，修改为您想要的 UTC 时间（注意：北京时间 = UTC时间 + 8小时。例如北京时间早 6 点，就是 UTC 22 点）。
4. 激活 Actions (最重要的一步！)
Fork 仓库后，默认 Actions 是禁用的。
请务必点击仓库顶部的 Actions 标签页 ➡️ 点击绿色的 I understand my workflows, go ahead and enable them 按钮。
然后在左侧选择 Update IPTV Lists，点击右侧的 Run workflow 手动跑一次，激活流水线。
⚠️ 五、 核心避坑指南（修改注意事项）
在修改代码或配置时，请务必避开以下“暗雷”：
⚠️ alias.txt 的主名绝对不能重复！
错误示范：在 CCTV 区写了 游戏风云,游戏风云HD，在 SiTV 区又写了 游戏风云,SiTV游戏风云。这会导致程序不知道把“游戏风云HD”分给谁，直接串台。
正确做法：确保逗号前面的主名全局唯一，例如改为 CCTV-游戏风云 和 SiTV-游戏风云。
⚠️ 警惕 AI 生成的 <thought> 标签！
如果您使用 AI 帮您批量生成 alias.txt 的别名，务必全局搜索并删除所有的 <thought>...</thought> 标签。否则这些思考过程会被程序当成频道名，直接导致正则崩溃、内存撑爆。
⚠️ GitHub Actions 的“黑名单”提交！
系统会自动生成 config/blacklist.txt 来拉黑垃圾源。如果您修改了 .yml 文件的 git add 步骤，请务必确保包含 config/blacklist.txt，否则每次运行完虚拟机销毁，黑名单就丢失了，系统会永远在同一个垃圾源上浪费时间。
⚠️ demo.txt 的格式！
demo.txt 里的频道名，必须与 alias.txt 里逗号前的第一个词（主名） 一字不差，多一个空格都会导致匹配失败。
⚠️ 本地运行产生的缓存！
如果您在本地电脑运行 python main.py，请务必确保仓库根目录有 .gitignore 文件，防止 __pycache__ 等 Python 缓存文件被误提交到 GitHub。
💡 结语：
这套系统具备极高的健壮性，不仅能自动干活，还能通过黑名单机制“自我学习”。祝您的 IPTV 列表永远高清、流畅！
